# 启用一个业务模块

仓库里有 15 个业务模块的源码，根 `pom.xml` 默认只启用 `system` 和 `infra`。接单时按需要放开。

## 先看清楚这件事

**除了 `system` 和 `infra`，其余模块在本仓库里没有生产建表脚本。** `sql/` 下只有 32 张 `system_` 表和 11 张 `infra_` 表。

各模块 `src/test/resources/sql/create_tables.sql` 是 H2 方言的单元测试夹具，**而且不全**——只覆盖了测试用到的表。举两个例子：`pay` 有 14 个 DO 实体但夹具只建 8 张表，`bpm` 有 8 个实体只建 3 张。拿它当生产 DDL 会缺表。

所以放开注释后能编译、能启动，但每个页面都是查不到表的 500。**建表脚本要从上游 ruoyi-vue-pro 完整版取**——那是作者维护的、和实体对得上的版本。

## 四步

### 1. 根 `pom.xml` 的 `<modules>` 放开注释

用聚合模块名。注意 `mall` 和 `iot` 在这里是聚合层：

```xml
<module>xiaoy-module-mall</module>   <!-- 含 product / promotion / trade / statistics / trade-api -->
<module>xiaoy-module-iot</module>    <!-- 含 iot-biz / iot-core / iot-gateway -->
```

### 2. `xiaoy-server/pom.xml` 的 `<dependencies>` 放开注释

这里用的是**叶子模块名**，和上一步不一样，最容易在这里踩坑：

| 模块 | 根 pom 写 | server pom 依赖 |
|---|---|---|
| 会员 | `xiaoy-module-member` | `xiaoy-module-member` |
| 工作流 | `xiaoy-module-bpm` | `xiaoy-module-bpm` |
| 报表 | `xiaoy-module-report` | `xiaoy-module-report` |
| 公众号 | `xiaoy-module-mp` | `xiaoy-module-mp` |
| 支付 | `xiaoy-module-pay` | `xiaoy-module-pay` |
| 商城 | `xiaoy-module-mall` | `xiaoy-module-product`、`xiaoy-module-promotion`、`xiaoy-module-trade`、`xiaoy-module-statistics` 四个都要 |
| CRM | `xiaoy-module-crm` | `xiaoy-module-crm` |
| ERP | `xiaoy-module-erp` | `xiaoy-module-erp` |
| 仓储 | `xiaoy-module-wms` | `xiaoy-module-wms` |
| 生产 | `xiaoy-module-mes` | `xiaoy-module-mes` |
| 物联网 | `xiaoy-module-iot` | `xiaoy-module-iot-biz` |
| 即时通讯 | `xiaoy-module-im` | `xiaoy-module-im` |
| AI | `xiaoy-module-ai` | `xiaoy-module-ai` |

两处都放开才生效：只改根 pom，模块会被编译但不会装进应用；只改 server pom，Maven 会去仓库里找一个没被构建的 artifact，直接报解析失败。

### 3. 补建表脚本

从上游 ruoyi-vue-pro 完整版的 `sql/mysql/` 里摘对应模块的 `CREATE TABLE` 和初始化 `INSERT`，按客户用的方言调整后执行。

`bpm` 额外要注意：Flowable 引擎自己的 `ACT_*` / `FLW_*` 表由 `application.yaml` 里的 `flowable.database-schema-update: true` 自动创建，不用手工建；但 `bpm_*` 业务表要自己补。

### 4. 菜单

`biz` 分支的 `system_menu` seed 里保留了全部模块的菜单和权限，补完 DDL 就能直接用，不需要额外操作。

（`edu` 分支把这些菜单删掉了，因为学生分支不需要一堆点不开的入口。）

## 模块之间的依赖

放开一个模块时，它依赖的模块也要一起放开：

| 模块 | 依赖 |
|---|---|
| `crm` | `bpm`（外加 `system`、`infra`） |
| `mall` | `member`、`pay`、`product`、`promotion`、`trade`、`trade-api`、`statistics` |
| `member` / `mp` / `im` / `ai` | `system`、`infra` |
| `bpm` / `pay` / `report` / `erp` / `wms` / `mes` / `iot` | `system` |

## 两个坑

**`xiaoy-module-ai` 在 JDK 8 下编译不过。** 它用了 `record` 和文本块，要 JDK 17+，同时得改根 `pom.xml` 的 `java.version`。而 Spring Boot 2.7 + JDK 17 这个组合本身没问题，但整个项目一起升的影响面要评估。

**`report` 模块引入积木报表（`jimureport-spring-boot-starter`）。** 它有自己的 URL 和租户处理方式，`application.yaml` 的 `xiaoy.tenant.ignore-urls` 里已经为 `/jmreport/*` 开了口子——这也意味着报表接口不走多租户过滤，多客户共用一套部署时要留意。

## 编译时间

启用的模块越多，`mvn clean install` 越慢，`bpm`（Flowable）和 `mall`（4 个子模块）尤其明显。只放开这次交付真正要用的。
