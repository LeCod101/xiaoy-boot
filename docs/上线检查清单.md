# 上线检查清单

商用交付前逐项过一遍。带 ⚠️ 的是**不改就是安全事故**，其余是会挨客户投诉的。

启用生产配置：`--spring.profiles.active=prod`，对应 `xiaoy-server/src/main/resources/application-prod.yaml`。
这个文件里所有密钥都读环境变量、不给默认值，缺变量会直接启动失败——这是故意的。

## ⚠️ 认证与口令

- [ ] **种子账号密码全部是 `admin123`**。`system_users` 里的 `admin`、`xiaoy`、`yuanma` 三个账号，上线前改密码或直接删掉不用的。
- [ ] **BCrypt 强度默认只有 4**（`$2a$04$`，上游为了演示登录快）。prod 配置已把 `xiaoy.security.password-encoder-length` 设成 10；注意旧哈希仍按 4 校验，必须让用户重设密码才会升级。
- [ ] **`xiaoy.security.mock-enable` 必须 false**。`application-local.yaml` 里是 `true`，此时用 `mock-secret`（默认字面量 `test`）就能伪造 token 过认证。prod 配置已显式关闭，别在启动参数里又打开。
- [ ] **`xiaoy.captcha.enable` 必须 true**。local profile 关掉了图形验证码，登录接口会被撞库。
- [ ] 前端 `.env.prod` 的 `VITE_APP_CAPTCHA_ENABLE` 与后端保持一致，否则登录页不显示验证码但后端要求验证码。

## ⚠️ 对外暴露面

- [ ] **`/druid` 控制台关闭**。`application-local.yaml` 和 `application-dev.yaml` 里 `stat-view-servlet.enabled: true` 且**没有账号密码**，等于把 SQL 明文、连接串、慢查询全部公开。prod 配置默认关闭。
- [ ] **Actuator 端点收窄**。dev profile 是 `include: '*'`，会连 `env`、`beans`、`heapdump` 一起放出去。prod 配置只留 `health,info`，且 `show-details: never`。
- [ ] **`/doc.html` 和 `/swagger-ui` 关闭**。prod 配置已关 `springdoc` 与 `knife4j`。
- [ ] Redis 设密码，且不绑公网地址。
- [ ] Spring Boot Admin（`/admin`）默认不启用；要用就配好账号密码，并放到内网。

## ⚠️ 密钥与凭据

- [ ] **`xiaoy.api-encrypt` 的 AES 密钥对是提交进仓库的明文**（`application.yaml` 里的 `request-key` / `response-key`）。启用接口加密时必须换新的，并同步改前端 `.env`——两边不一致就是全站请求解不开。
- [ ] 数据库、Redis 密码走环境变量，不写回 yaml，不进 git。
- [ ] `sql/` seed 里所有 `YOUR_*` 占位符换成真值或删掉对应行：
  - `infra_file_config` 的 OSS `accessKey` / `accessSecret`
  - `system_sms_channel` 的短信 `api_key` / `api_secret`
  - `system_social_client` 的 `client_id` / `client_secret`
  - `system_mail_account` 的邮箱账号密码
  - `system_oauth2_client` 的 `secret`
- [ ] 检查一遍 `git log -p` 里没有把客户的密钥提交进去。这个仓库是公开的，`biz` 分支只放基座，客户代码和配置放客户自己的私有仓库。

## 数据与初始化

- [ ] **Quartz 表要手工建**。prod 配置是 `initialize-schema: NEVER`，执行对应方言的 `sql/*/quartz.sql`。
- [ ] 清理示例数据：`system_tenant` 的示例租户（`websites` 里还有 `www.xiaoy.cn`）、`system_notice` 的演示公告、`system_oauth2_client` 里的 SSO 演示客户端、`infra_` 的代码生成案例。
- [ ] 确认 `id-type: NONE` 的「智能」ID 策略在客户用的数据库上落到了预期模式（MySQL 走 AUTO，Oracle / PostgreSQL / Kingbase 走 INPUT）。
- [ ] 备份策略、慢 SQL 阈值（prod 设的是 200ms）按客户的数据量调。

## 前端

- [ ] `.env.prod` 的 `VITE_BASE_URL` 改成真实后端地址。仓库里现在是 `http://localhost:48080`。
- [ ] `VITE_BASE_PATH` 按部署路径设置（根路径部署就是 `/`）。
- [ ] `pnpm build:prod` 后确认 `dist/` 里没有 sourcemap（`.env.prod` 的 `VITE_SOURCEMAP` 应为 false）。

## 需要决策、没有标准答案的

- [ ] **多租户**。`xiaoy.tenant.enable` 默认 true。单客户交付通常关掉更省事，但关之前确认业务表的 `tenant_id` 怎么处理——已有数据的租户字段不会自动清理。
- [ ] **XSS 过滤**。`xiaoy.xss.enable` 默认 false。打开会过滤富文本字段（比如系统通知的 HTML 正文），需要配 `exclude-urls` 放行。
- [ ] **日志级别**。prod 配置是 `cn.xiaoy: info`。local / dev 把各模块的 Mapper 设成了 debug，会打印全部 SQL，生产开着会把磁盘刷满。
- [ ] 是否需要 HTTPS 终止、反向代理下的 `X-Forwarded-*` 处理、真实 IP 获取。

- [ ] 确认 `mvn clean install -DskipTests` 在客户的 JDK 版本上通过。
